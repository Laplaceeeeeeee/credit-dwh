## 一、结论先行

**结论：作为"简历项目"，阶段三之前的内容 —— 设计上是合格且明显偏上的；但它现在还不是一个能投递的简历项目，缺口不在深度，而在"技术证据"。**

三句话概括：

1. **方向选得对，且设计思路比 90% 的学生数仓项目更专业。** 分层架构、星型模型、拉链表、Vintage、迁徙率、口径字典、数据质量校验 —— 这套组合拳直击银行数据岗的考核点。
2. **真正的问题不是"深度不够"，而是"深度的载体缺失"。** 你规划的所有亮点（Hive 分区、增量、倾斜、性能对比）几乎全部被放进了**阶段三**，而阶段三在你自己的时间表里是 2027.01–03 —— 也就是**投递季之后**。结果就是：简历上能写的技术栈只剩 `Python(pandas) + MySQL`，而这是"数据分析"的画像，不是"数据开发"的画像。
3. **广度有明确硬缺口：调度、Linux/Shell、版本管理、可复现工程。** 这四项在银行数仓岗的 JD 里出现频率极高，而本文档**一次都没有提到**。

**如果只能改一件事**：把"调度 + 增量 + Linux/Shell + Git"这四样补进阶段二（约 12–16 小时额外投入），而不是等阶段三。这一条的价值 > 后面所有其他建议之和。

### 3.2 两个文档里已经做对的"高价值判断"

**① 申请时点信息 vs 表现期信息（§0.5）**
这是信贷数据工程的职业分水岭。绝大多数学生做 LendingClub 项目时，会把 `total_rec_prncp`、`loan_status` 当初选特征用，做出一个"准确率很高"的模型，然后在面试中被打穿。你在设计阶段就把这件事写进铁律，说明你具备**数据泄漏防控意识**。

> ⚠️ **但**：简历段落（§7.2）里一个字都没提。必须补一句 —— 否则这个最强的亮点在筛简历阶段是隐形的。

**② 数据质量校验体系（§5.3）**
"汇总一致性 = DWD 明细重算值"这一条，是数据开发面试中的经典追问点。你把它写成了表，很好。同样**简历里没体现**。

### 3.3 三个真实的深度漏洞（面试会被追穿）

**(1) "批准率"指标在 LendingClub 上算不出来 —— 文档还在鼓励你算**

§4.1 写了"批准率 = 批准笔数 / 申请笔数"，脚注说"若数据只有放款样本，需说明局限"。这是对的，但**太软了**。你下载的是 `accepted_*.csv`，即**只有获批样本**。这意味着：

- 批准率**必须删除**，不能上简历（分母不存在）
- 所有风险指标都受**样本选择偏差**影响：你观测到的是"被批准且放款的人"的表现，不是全客群
- 若要补批准率，需另下 `rejected_2007_to_2018Q4.csv`（只有申请金额/日期/风险等级等极少数字段，无表现期）

**建议**：把这一条从"局限说明"升级为**简历上的主动加分句** —— "针对数据集仅含放款样本的局限，明确剔除批准率类指标并说明幸存者偏差影响范围"。面试官听到这句会直接给你加一档。

**(2) §6.2 的"业务解读"示例是**过度归因**，有被反问的风险**

文档示范的解读是：

> "2018 年逾期率上升，从 Vintage 表看主要是 2018-Q2 批次在 MOB6 后表现恶化，**可能与当期客群下沉或授信政策放松有关，建议核查该期准入规则**"

后半句（"客群下沉""政策放松""核查准入规则"）在**这份数据里无法验证** —— 你既没有准入规则、没有拒绝样本、也没有宏观或政策数据。有经验的面试官会立刻反问："你怎么证明是政策放松？" 一旦答不上来，反而暴露"为了讲故事而编因果"。

**改写方向（同样有业务感，但站得住）**：
> "2018-Q2 批次 MOB6 逾期率较 2017 年同 MOB 高出 X 个百分点。**从数据内可验证的口径看**，该批次在 `grade` C–E 段占比提升 Y%、平均 `int_rate` 上升 Z%，风险敞口向次级客群迁移；至于驱动因素是准入策略变化还是外部环境，**当前数据无法区分，需补充申请侧与拒绝样本数据**。"

**"明确说出我不能证明什么"比"给出一个漂亮因果"更像专业人。**

**(3) 拉链表（SCD2）在 LendingClub 上**没有真实数据支撑**，存在"为做而做"痕迹**

§3.4 要建 `dim_customer_scd2`，记录客户评级/收入的历史变化。但：

- LendingClub 是**一次性快照数据**，`annual_inc`、`grade` 都是**放款时点值**，没有历史切片
- 也就是说，你无法构造出真实的"属性变更"序列，只能**人为造几条假变更**来演示拉链逻辑

这会被追问："你的 SCD2 数据从哪来的？" 如果答"我模拟的"，杀伤力很大 —— 拉链表瞬间从"懂数仓"变成"背概念"。

**三个可行出路（按推荐度排序）**：
1. **换成有真实时间维度的对象**：对 `loan_status` 或客户风险等级按**月末快照**（month-end snapshot）构建**快照事实表**（periodic snapshot fact），这是有真实数据支撑的、同样体现历史追踪能力的建模方式，且更贴合信贷场景
2. **多期数据拼接**：用 Kaggle 上 LendingClub 的多个年度快照文件（若可得）拼出真实的属性变更
3. 保留 SCD2，但**明确标注为"演示性质的实现"**，并在文档中说明真实场景下数据来源应为 CRM/核心系统的每日全量或 binlog 抽取

**推荐路线 1**，因为它把"假数据"换成了"真结构"，难度不降，可信度大涨。

## 五、这个项目在简历池中的位置（"独特性"判断）

**诚实的定位：中上偏上，但不是稀缺。**

LendingClub 是数据岗简历里**最常见的公开数据集之一**，Vintage / 迁徙率也有大量人在做。你的差异化**不在选题，而在完成度与文档质量**：

| 竞争者层级 | 占比估计 | 特征 | 你所在位置 |
|---|---|---|---|
| L1 只做 EDA + 几个图表 | 大量 | 用 pandas 画几张图，讲"发现了规律" | — |
| L2 EDA + 建模预测违约 | 很多 | 上 XGBoost 刷 AUC，讲模型 | — |
| **L3 分层数仓 + 口径 + 质量校验** | 少 | 讲架构、讲口径、讲可信 | ⬅ **你规划的落点** |
| L4 L3 + 大数据组件 + 调度 + 性能优化 | 很少 | 讲规模、讲调优、讲权衡 | ⬅ **阶段三的落点** |

**结论**：阶段二结束时你是 **L3**，在**银行**数仓岗的简历池里属于**有竞争力**（因为银行比互联网更看重口径与建模而非组件军备）；但在**互联网大厂**数仓岗里，L3 只是及格线，因为那里必然要求 Hive/Spark 实战。

**因此结论是定向的**：
- 投**银行/券商**：阶段二的深度**够用**，广度**需补调度+Linux+Git**（见 §4.2）
- 投**互联网大厂**：**不够**，必须把阶段三的 Hive/Spark 提前

### ⚠️ 关于数据规模的一个隐性风险

226 万行 × 151 列，压缩后 374 MB —— 这个量级**在单机 pandas 上完全可以跑**（裁剪列后在内存中约 1–2 GB）。这会带来一个反问：

> "你这数据量用 pandas 就够了，为什么要上数仓/Spark？"

**这个问题必须准备答案，而答案可以是加分的**：

> "单机确实能跑，我实测裁剪列后约 X GB 内存。但我用数仓分层不是为了扛量，而是**为了让口径可复用、让每个指标有唯一可信来源、让 ODS 可回溯** —— 这三件事和体量无关。同时在阶段三我把同一套逻辑迁到 Hive 分区表，对比了单机与分布式的耗时与资源，明确了这个数据量的**引擎选择边界**。"

**"我知道我的数据量不需要分布式，我选它是为了迁移验证"** —— 这个回答比"我数据大所以用大数据"成熟得多。

```
  批次 X 个百分点，风险敞口向次级评级段迁移
```

## 九、最终裁决

| 问题 | 回答 |
|---|---|
| **作为研究生实习简历项目是否合适？** | ✅ **合适，且方向精准**（银行/券商数仓岗）；但需按 §六 打补丁才可投递 |
| **深度够吗？** | 🟡 **业务与建模深度：够，甚至超出预期。技术深度：不够** —— 且缺的部分恰好是银行 JD 的硬要求 |
| **广度够吗？** | 🟡 **建模/指标/质量三维足够；调度、Linux、Git、SQL 工程化四项硬缺口**，补上后即达标 |
| **最大的单点风险？** | 把 Hive/Spark 全部押在阶段三（2027.01–03），**晚于投递季**，导致简历技术栈画像偏"分析"而非"开发" |
| **最高性价比动作？** | 阶段二内补 **调度 + 增量 + Linux/Shell + Git + SQL 实现**（约 16–23h），并用 SQL 完成指标而非等 Hive |
| **相对竞争力的诚实定位** | 银行池：**上游**（L3 / L4 之间）；互联网池：**及格线附近**（L3） |

### 一句话总结

> **这个项目的设计质量已经超过它的实现进度 —— 你的问题不是"想得不够深"，而是"最好的深度都排在了投递季之后"。把调度、增量、Linux、Git 和 SQL 实现搬进阶段二，它就从"一份很好的学习计划"变成"一份能打的研究生实习简历项目"。**
