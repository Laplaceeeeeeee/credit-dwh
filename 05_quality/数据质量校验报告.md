### Q8 无未来信息 ✅ ⭐ 本项目最有价值的一条

| 项 | 值 |
|---|---|
| 规则 | **申请时点事实表中不含任何表现期字段** |
| 级别 | ERROR |
| 实际 | 泄漏字段 = **无** |
| 校验方式 | 用 `config.LEAKAGE_BLACKLIST`（44 个字段）扫描表结构 |

**这一条在防什么**：**数据泄漏（Data Leakage）** —— 把"放款后才知道的信息"
当成"放款时就能用的信息"。

| 字段类别 | 例子 | 什么时候知道 |
|---|---|---|
| 申请时点信息 | `loan_amnt`、`grade`、`annual_inc`、`dti` | 申请那一刻 |
| **表现期信息** | `loan_status`、`out_prncp`、`total_rec_prncp` | **放款后** |

**如果混用会怎样**：以"分析什么样的人容易逾期"为例，
若用了 `out_prncp`（剩余未还本金）——
已核销的人剩余本金可能是 0，按时还完的人剩余本金也是 0，
于是得出"剩余本金低的人风险低"这种**完全错误**的结论。

> 🔑 **面试话术**：
> "我不是靠自觉避免数据泄漏，是靠**表结构约束和自动化校验** ——
> 字段黑名单校验一旦发现申请时点表里出现 `out_prncp` 这类表现期字段就直接 fail。"

**三道防线**：

| 防线 | 手段 | 实现位置 |
|---|---|---|
| 一 | **DDL 物理分表** | `sql/ddl/01_schema.sql` |
| 二 | 代码白名单 | `config.APPLY_COLS` |
| 三 | **自动校验**（本条） | `src/dq_check.py` |

## 3. 校验结果留痕

每条检查结果写入 `dq_check_result`，带 `batch_id` 便于追溯：

```sql
SELECT check_name, check_level, passed, actual_value
FROM dq_check_result
WHERE batch_id = '20260917160658-939e2f'
ORDER BY check_id;
```

| 字段 | 用途 |
|---|---|
| `check_name` | 检查项名称 |
| `check_level` | ERROR / WARN |
| `passed` | 1 通过，0 失败 |
| `actual_value` / `expect_value` | 实际值与期望值（便于定位） |
| `batch_id` | 批次标识，可对比不同批次 |
| `check_time` | 校验时间 |

**累计批次**：3 个（子集验证 → 全量首次 → 全量修复后）

## 4. 已知边界与不覆盖项

**本校验体系不覆盖以下内容**（它们属于数据边界，不是质量问题）：

| 项 | 说明 |
|---|---|
| 幸存者偏差 | 数据仅含已放款样本，无法通过校验发现 |
| DPD 档位的推导误差 | 档位是按规则推导的，非原始逐月状态 |
| `member_id` 缺失 | 已作为设计约束处理（不建客户维），非数据错误 |
| FICO <660 档样本不足 | 属样本量问题，非数据质量 |

**校验体系覆盖的是**：**数据在管道里是否被正确搬运与加工**。
业务层面的偏差需由《数据边界与偏差说明》声明。

## 5. 如何重跑

```powershell
$PY = ".\.venv\Scripts\python.exe"
& $PY -m src.dq_check
```

**退出码语义**：

| 退出码 | 含义 |
|---|---|
| 0 | 全部 ERROR 级校验通过 |
| 1 | 存在 ERROR 级失败 —— **流水线应中止** |

**在流水线中的位置**：`run_pipeline.ps1` 的第 08 步（最后一步）。
它失败会导致整条流水线返回非 0，避免"数据有问题但没人发现"。
