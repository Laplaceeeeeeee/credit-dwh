## 5. ⭐ 本次实配发现并已修正的问题（含一个数据事实错误）

| # | 问题 | 现象 | 处理 |
|---|---|---|---|
| 1 | **`mysql --batch` 仍会输出表头** | TSV 比 MySQL 多 1 行 → 脚本的行数自校验直接报错（**这正是它存在的意义**） | 加 `--skip-column-names`；已写入排错手册 |
| 2 | ⭐⭐ **NULL 表示与文档写的不一样** | `--batch` 把 NULL 打成**字面量 `NULL`**，不是 `\N`（实测 `SELECT NULL,'a',''` → `NULL<TAB>a<TAB><TAB>`）；只有 `INTO OUTFILE ... ESCAPED BY '\\'` 才是 `\N` | 改成统一走 OUTFILE；`nullValue` 相应设为 `\N` |
| 3 | ⭐⭐ **5 GB 结果集流经 `docker exec` 把 Docker daemon 卡死** | 导出快照表时 daemon 对所有 API 路由返回 **500**，`docker ps`/`info`/`logs` 全废，只能重启 Docker Desktop（前两张小表 288 MB/173 MB 正常） | 大表改用**服务端 `SELECT ... INTO OUTFILE` + `docker cp`**，125 秒稳定完成 |
| 4 | ⭐ **PySpark 的 `spark.sql()` 只接受单条语句** | `spark.sql("USE db; SELECT ...")` 报 `PARSE_SYNTAX_ERROR ... at or near 'SELECT'`（`spark-sql` CLI 支持分号拼接，PySpark 不支持） | 改用 `spark.catalog.setCurrentDatabase()`；已修正文档里的代码 |
| 5 | ⭐ **`SET hive.exec.dynamic.partition` 会告警** | Spark 提示：*"might not work, since Spark doesn't support changing the Hive config dynamically"*，建议用 `spark.hadoop.*` 前缀静态配置 | 装载 SQL 里保留 SET（datasource 路径真正生效的是 `partitionOverwriteMode`），并在注释里说明两条路径的差别 |
| 6 | ⭐ **放款时间跨度记错了（数据事实错误）** | 阶段二文档写 `Apr-2008 ~ Sep-2018`；实际是 **2007-06 ~ 2018-12（139 个月）** —— 由基准值"放款月数=139"顶出来，随后在源 Parquet 与 MySQL 双重验证；`配置进度与问题记录.md`（归档手册，不入库）里当年写的"指导书原值 2007-06~2018-12"才是对的 | 已更正 README / 简历材料 / EDA / 分析报告 / 数据边界说明 / runbook / 实施手册（8 个文件）；并在 EDA 报告留下更正说明 |
| 7 | 附带影响：`dim_date` 覆盖不到最早 6 个月 | `dim_date` 建的是 2008-01-01 ~ 2019-12-31，**不覆盖 2007-06 ~ 2007-12 的 603 笔贷款** | 记入数据边界（阶段三不依赖 dim_date；如后续要按日期维关联需补建） |
