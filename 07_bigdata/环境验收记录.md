### ⚠️ ③ 的检查方法要改（指导书原文的写法在本镜像里失效）

`apache/hive` 镜像**没有安装 `ss` 也没有 `netstat`**，所以
`ss -tlnp | grep 9083` 会直接输出 `NOT LISTENING` —— **是假阴性**。
可靠写法（三选一）：

```powershell
# ① 最可靠：真实 TCP 连接（端口已发布到宿主）
try { $c = New-Object Net.Sockets.TcpClient; $c.Connect('127.0.0.1',9083); "OK $($c.Connected)"; $c.Close() } catch { "FAIL" }

# ② 不依赖任何工具：直接读 /proc/net/tcp 与 tcp6（9083 = 0x237B，状态 0A = LISTEN）
docker exec bd-metastore grep -i 237B /proc/net/tcp
docker exec bd-metastore grep -i 237B /proc/net/tcp6     # ⭐ 别漏了 tcp6，本机就落在 v6 表

# ③ 看日志
docker logs bd-metastore 2>&1 | Select-String 'Starting Hive Metastore Server'
```

## 5. ⭐ 与指导书默认值的三处偏差（都已在配置文件里注明原因）

### 偏差 1：Spark 侧缩容（内存适配）

本机 Docker 虚拟机只有 **7.64 GB**，而指导书默认给 worker `SPARK_WORKER_MEMORY=3g` + `mem_limit 5g`。
实测宿主机物理内存仅 15.8 GB、当时可用 6.2 GB，**把 Docker 调到 12 GB 会让 Windows 自己换页**，
所以选择缩容而不是改 Docker 全局设置：

| 项 | 指导书默认 | 本机实际 |
|---|---|---|
| `SPARK_WORKER_MEMORY` / `mem_limit` | 3g / 5g | **2g / 2800m** |
| `SPARK_WORKER_CORES` / `cpus` | 6 / 6 | **4 / 4** |
| Spark master | — / 4g | **2 cpus / 1500m** |
| Metastore | 1–1.5 GB | **1500m** |
| 元数据库 | 512 MB–1 GB | **1g** |
| driver / executor memory | 未显式设置 | **1500m / 2g（显式写死，避免默认 1g driver 在大 shuffle 时 OOM）** |

> ⚠️ **跑 E1–E5 的重任务前先腾内存**：`docker stop credit-dwh-mysql`。
> （第 13 步导出 TSV 需要它，导完再停。）

### 偏差 2：Metastore 必须以 root 运行（**指导书漏掉的真实缺陷**）

镜像默认用户是 `uid=1000(hive)`，而命名卷目录属主是 `root:root`，于是建库时直接失败：

```
MetaException(message:Unable to create database path
  file:/opt/spark/warehouse/credit_dwh_lc.db, failed to create database credit_dwh_lc)
```

修法（已落地）：给 `metastore` 服务加 **`user: root`**，与 Spark 服务保持一致。
> 另一种修法是 `chown 1000:1000` 那个卷目录；但 Spark 侧以 root 写文件，
> 后续删/改文件时 hive 用户仍可能碰壁 —— **统一用 root 更省事**。

### 偏差 3：Metastore client 用内置 2.3.9，而不是 `jars=maven` + 3.1.3

指导书默认写 `spark.sql.hive.metastore.version=3.1.3` + `jars=maven`。实测：

- `jars=maven` 会走 **Ivy 首次解析**，跑 **7 分钟仍未完成**（随后超时中断）；
  容器出网本身正常（`curl repo1.maven.org` 返回 200），所以**不是网络问题，是 Ivy 慢**；
- 而且 Ivy 缓存落在容器**可写层** `/root/.ivy2`，**容器一重建就没了** —— 对反复重建的教学环境很脆弱；
- 改用 **Spark 内置的 Hive 2.3.9 client 直连 HMS 3.1.3**：`SHOW DATABASES` **4.4 秒**返回，
  建库/建表/分区/插入/查询**全部通过**。

**代价与诚实说明**：client(2.3.9) 与 server(3.1.3) 版本不一致，
属于"可用但不推荐在生产使用"的组合。生产上应统一版本，两条可复现的路子：
① `jars=path` + 宿主机预下载 jar 目录挂进容器（推荐）；
② `jars=maven` + **给 `/root/.ivy2` 挂命名卷**（否则缓存随容器丢失）。
> ⭐ 这个取舍本身就是面试素材：**"能跑通"和"生产可用"是两件事，要能说清边界。**
