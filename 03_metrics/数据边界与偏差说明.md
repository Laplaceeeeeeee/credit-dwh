# 数据边界与偏差说明

> **本文档的目的**：明确本数据集"**能回答什么**"与"**不能回答什么**"。
> 主动声明边界是数据专业性的体现，**不是项目缺陷**。
> 全部结论均为本地实测（2026-09-15）。

---

## 1. 数据来源与范围

| 项 | 值 |
|---|---|
| 来源 | LendingClub 公开数据集 `accepted_2007_to_2018Q4.csv.gz`（374.4 MB） |
| 物理行数 | 2,260,702 |
| 剔除页脚 | **33 行**（散布全文，非仅末尾） |
| 表头 | 1 行 |
| **真实数据行** | **2,260,668** |
| 字段数 | 151 → 保留 **137**（剔除 14 个整列为空） |
| 放款时间跨度 | **Apr-2008 ~ Sep-2018** |
| 无 | 拒绝样本、全量申请样本 |

---

## 2. 十项核心边界

### 边界 1：仅含放款样本 → 幸存者偏差 🔴

- **实测**：本文件为 `accepted_*`，只含**已批准并放款**的贷款
- **影响**：所有风险指标（不良率、Vintage、迁徙率）都在"已放款客群"内计算，
  **不可外推至全申请客群**。真实全客群不良率会**低于**本数据
- **处理**：
  - 所有结论**限定表述**为"在已放款客群内"
  - **删除**批准率 / 通过率（分母不存在）

---

### 边界 2：`member_id` 整列为空 → 无法建客户维 🔴

- **实测**：2,260,668 行中该列**非空值为 0**，LendingClub 已移除该字段
- **影响**：**不存在识别"同一客户多笔贷款"的键**，
  客户级汇总、一人多贷分析、客户生命周期分析**全部不可做**
- **处理**：
  - 从设计中剔除该列
  - 客户维**降级为申请人画像维** `dim_applicant`（粒度 = 一笔贷款，主键 = `loan_id`）
  - ❌ **不采用**：用 `annual_inc + addr_state` 等拼"伪客户 ID" ——
    会造成错误关联，让统计失真

> 🔑 **面试话术**：
> "这份数据的会员 ID 列是空的。我**没有**伪造一个客户主键，
> 而是把它降级为申请人画像维，并在文档里写明'客户级分析不可做'。
> 这属于数据边界，不是实现缺陷。"

---

### 边界 3：页脚行散布全文（33 行）🔴

- **实测**：文件由**多个年度分段拼接**而成，段间夹着章节标题与汇总行：
  ```
  16 对：Total amount funded in policy code 1/2: ...
   1 行：Loans that do not meet the credit policy,,,,...
  首次出现于第 421,096 行，间隔约 10~23 万行一次
  ```
- **影响**：`skipfooter=1` **只删最后一行**，另外 32 行会混进 `id` 列，
  并导致 pandas 把 `id` 推断为字符串，引发 schema 不一致
- **处理**：全文件扫描，按"`id` 首字段必须为纯数字"剔除；
  页脚原文留证于 `data/clean/footer_line.txt`

---

### 边界 4：14 个字段整列为空

- **实测**：`member_id`、`revol_bal_joint`、7 个 `sec_app_*` 等共 **14 列**全为空
- **处理**：预处理阶段整体剔除，保留 **137 列**

---

### 边界 5：状态为**最终快照**，非逐月历史 🔴

- **实测**：`loan_status` 是数据提取时点的**最新状态**，不是逐月状态序列
- **后果**：
  - 严格意义的**迁徙率无法直接计算**
  - 本项目的 DPD 档位是按"距最后还款月数"**规则推导**的
- **处理**：在所有相关产出物中**明确标注"推导值，非原始逐月状态"**
- **连带影响**：推导规则使核销状态滞后（推定核销月 = 最后还款月 + 6），
  因此 **MOB < 12 时只统计 `CHARGED_OFF` 会低估风险**，
  需把 `DPD_120_PLUS` 一并视为"已暴露风险"

---

### 边界 6：缺少策略与宏观数据 🔴

- **实测**：无准入规则、无拒绝客群、无催收记录、无宏观经济指标
- **影响**：**无法归因**"为什么某批次风险上升"
- **处理**：分析结论**只陈述数据内可验证的事实**，不推断外部原因

> ⚠️ **典型反例（必须避免）**：
> ❌ "2018 年逾期率上升，**可能与客群下沉或授信政策放松有关**"
> —— 本数据**无法验证**这一因果，面试官一问"你怎么证明"就翻车。
>
> ✅ 正确写法：分两段
> ① **数据内可证**："该批次 C–E 级占比从 X% 升至 Y%，加权平均利率从 A% 升至 B%"
> ② **明确边界**："至于驱动因素是准入调整还是外部环境，**当前数据无法区分**"

---

### 边界 7：样本期截至 2018Q4

- **实测**：`issue_d` 最晚为 **Sep-2018**
- **影响**：晚批次观察期不足，MOB12+ 数据不完整
- **处理**：Vintage 矩阵按**实际可用 MOB 截断**，不补全、不插值

---

### 边界 8：数据快照月为 2019-03

- **说明**：`dws_loan_snapshot_m` 的观测月截至 2019-03（非终态贷款的账龄参考点）
- **影响**：非终态贷款的 `mob_final` 是相对该快照月计算的，非真实结清时间

---

### 边界 9：`grade` 是平台给定评级，非独立评估

- **影响**：`grade` 可能已内含本文未观测到的信息，
  因此"评级与不良率单调"**不能**直接证明"评级模型有效"
- **处理**：结论只描述"在已放款客群内，评级与不良率呈严格单调关系"

---

### 边界 10：金额与利率为合同值，未做通胀/资金成本调整

- **影响**：跨年份比较金额规模时未考虑货币时间价值
- **处理**：趋势分析只做**相对变化**描述，不做绝对值跨期可比性断言

---

## 3. 边界对指标的影响矩阵

| 指标 | 是否受影响 | 影响方式 | 应对 |
|---|---|---|---|
| 放款金额 / 笔数 | 否 | 本身就是已放款口径 | — |
| **不良率** | 是 | 幸存者偏差；须限定终态 | 限定客群表述 + `is_terminal=1` |
| Vintage | 是 | 晚批次观察期不足；推导规则滞后 | 按可用 MOB 截断 + 标注推导 |
| 迁徙率 | 是 | 无逐月状态，档位为推导值 | **方向可信，数值谨慎** |
| 期末未偿余额 | 是 | 快照月固定为 2019-03 | 标注观测时点 |
| **批准率** | **不可计算** | 无分母 | **删除** |
| **客户级任何指标** | **不可计算** | `member_id` 整列为空 | **放弃该维度** |
| **一人多贷 / 客户生命周期** | **不可计算** | 无客户识别键 | **放弃该分析** |
| 跨年份规模比较 | 是 | 未做通胀调整 | 只做相对变化描述 |

## 4. 面试一分钟话术

> "这份数据有**三个硬限制**，我在设计阶段就处理掉了。
>
> **第一，只有已放款的样本、没有拒绝客群** —— 所以我**删掉了批准率**，
> 因为分母不存在；并且把所有风险结论限定在'已放款客群'内表述，不做外推。
>
> **第二，会员 ID 列是空的**，根本不存在识别同一客户的键 ——
> 我**没有**用其他字段拼一个伪客户 ID，而是把客户维降级为申请人画像维，
> 粒度是一笔贷款，并在文档里写明'客户级分析不可做'。
>
> **第三，文件里散布着 33 行页脚**，不是只在末尾。这个文件是多个年度分段拼起来的，
> 段间夹着章节标题和汇总行。只跳过最后一行是错的 —— 我做了全文件扫描把这 33 行剔掉。
>
> 另外，需要逐月状态的迁徙率，我用规则推导并**标注了假设**。
> 我宁可写清'这是推导的、早期 MOB 会滞后'，
> 也不想让一个看起来漂亮的数字失去可信度。
>
> 同样，某批次逾期率上升，我能证明的是'该批次 C–E 级占比从 X% 升到 Y%'，
> 但**我不能证明是准入策略放松导致的** —— 那需要申请侧和策略变更数据。
> 我更愿意说清我证明不了什么，而不是给一个漂亮的因果。"

> 🔑 **语气很重要**：上面没有一处是"我的项目不完善"式的检讨，
> 全是"我识别了边界并做了处理"的工程判断。
> **主动声明边界叫专业，自我检讨叫不自信** —— 同样的内容，两种讲法效果差一个档次。
