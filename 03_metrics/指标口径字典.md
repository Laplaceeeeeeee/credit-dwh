# 指标口径字典

> **版本**：v1.0 ｜ **生效日期**：2026-09-15 ｜ **运行规模**：可切换（`config.MAX_ROWS`）
> **规则**：所有指标必须从本文件取定义，脚本中禁止出现"另一套算法"。
> 口径变更需更新本文件并**升版本号** + 附变更说明。

---

## 口径总则

1. **一切口径常量写在 `src/config.py`**（`BAD_STATUSES` / `TERMINAL_STATUSES` /
   `DPD_MAP` / `LEAKAGE_BLACKLIST`），改口径只改一处。
2. 涉及表现期的指标，**必须基于 `dwd_loan_perf_fact` 且限定 `is_terminal = 1`**。
3. 涉及"批次"的指标，批次 = 放款月 `issue_month`。
4. 金额一律用 `funded_amnt`（实际放款额），不用 `loan_amnt`（申请额）。

## M01 放款金额 / 放款笔数

| 项 | 内容 |
|---|---|
| 业务含义 | 统计期内成功放款的总额与笔数 |
| 计算公式 | `SUM(funded_amnt)` / `COUNT(1)` |
| 数据来源 | `dwd_loan_fact` |
| 可用维度 | issue_month / grade / purpose / addr_state |
| 口径说明 | 用 `funded_amnt`（实际放款）而非 `loan_amnt`（申请） |
| 边界 | 仅含已放款样本 |

## M02 不良率（终态口径）⭐

| 项 | 内容 |
|---|---|
| 业务含义 | 已形成终态的贷款中，发生核销/违约的占比 |
| 计算公式 | `SUM(is_bad) / COUNT(1) WHERE is_terminal = 1` |
| 数据来源 | `dwd_loan_perf_fact` |
| 口径说明 | 不良 = `loan_status IN ('Charged Off','Default','Does not meet...Charged Off')` |
| ⚠️ **易错点** | **必须限定 `is_terminal = 1`**，否则 `Current`（全量占 38.85%）会稀释分母 |
| **实测对照** | 正确 19.9287%（子集）｜ 错误 17.5455% → **低估 2.38 个百分点** |
| 边界 | 幸存者偏差：仅反映已放款客群 |

```sql
-- ✅ 正确
SELECT SUM(is_bad) / COUNT(*) FROM dwd_loan_perf_fact WHERE is_terminal = 1;
-- ❌ 错误（分母混入仍在还款的贷款）
SELECT SUM(is_bad) / COUNT(*) FROM dwd_loan_perf_fact;
```

## M06 Vintage 逾期率 ⭐

| 项 | 内容 |
|---|---|
| 业务含义 | 同一放款批次的贷款在**不同账龄**下的累计不良率 |
| 计算公式 | `SUM(ever_bad) / COUNT(1)`，按 `(issue_month, mob)` 分组 |
| 数据来源 | `dws_loan_snapshot_m` |
| 账龄定义 | `mob = 观测月 − 放款月` |
| **为什么做 Vintage** | 不同月份放款的账龄不同。**直接比总逾期率会误导**——老批次暴露更充分。Vintage 把账龄对齐后才能公平比较 |

### ⚠️ 实现要点 1：累计不良**不能**用 `SUM(is_bad_month)`

`is_bad_month` 是"该月末是否处于核销状态"的逐月标记。
一笔贷款在 MOB15 被核销后，MOB15~24 的快照**都是 1**，
直接 `SUM` 会把同一笔**重复计数**，导致累计不良率随 MOB 虚高。

```sql
-- ✅ 正确：用窗口函数取"曾核销"标志
MAX(is_bad_month) OVER (
  PARTITION BY issue_month, loan_id ORDER BY mob
  ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
) AS ever_bad

-- ❌ 错误
SUM(is_bad_month)
```

**口径自检**：累计不良率必须随 MOB **单调不减**。
校验 SQL：`sql/dq/check_vintage_monotonic.sql`（期望返回 0 行）。实测 **0 行** ✅

### ⚠️ 实现要点 2：DPD 档位为**规则推导**，早期 MOB 必然滞后

本项目无逐月还款状态，档位由"距最后还款月数"推导，
核销推定月 = 最后还款月 + 6。因此：

| MOB | 实际现象 | 正确读法 |
|---|---|---|
| ≤ 6 | 只有 `DPD_120_PLUS` 累积，**无** `CHARGED_OFF` | `DPD_120_PLUS` 是核销的前置信号 |
| ≥ 12 | 开始出现 `CHARGED_OFF` | 此时 `CHARGED_OFF` 才可用 |

> 🔑 **MOB < 12 时，只统计 `CHARGED_OFF` 会低估风险。**
> 正确做法是 `DPD_120_PLUS + CHARGED_OFF` 一并视为"已暴露风险"。

## M07 迁徙率（Roll Rate）⚠️

| 项 | 内容 |
|---|---|
| 业务含义 | 本期处某档位的贷款，下期迁徙到各档位的比例 |
| 计算公式 | 自关联 `mob+1`，`COUNT(*) / SUM(COUNT(*)) OVER (PARTITION BY 期初月, 期初档位)` |
| 数据来源 | `dws_loan_snapshot_m` |
| ⚠️ **重要局限** | 档位为**规则推导值**，非原始逐月状态。"单向恶化"部分**来自规则本身**（`ms` 只增不减），不完全是真实行为 |
| 可用性 | **方向可信**（逾期确实单调恶化），**具体数值需谨慎** |
| 正确用法 | 做定性描述，不做催收效果评估或未来不良预测 |

**实测（子集，最近观测月）**：

| 期初 → 期末 | 迁徙率 |
|---|---|
| CURRENT → CURRENT | 96.51% |
| CURRENT → DPD_1_30 | 3.49% |
| DPD_31_120 → DPD_120_PLUS | 52.70% |
| DPD_120_PLUS → CHARGED_OFF | 2.71% |
| CHARGED_OFF → CHARGED_OFF | 100.00% |
