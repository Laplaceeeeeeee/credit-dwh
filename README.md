## 🎯 项目一句话

> 把一份 226 万行的原始信贷放款流水，加工成一套能回答
> "**这笔贷款会不会逾期 / 哪批客户质量在恶化 / 风控策略改完有没有效果**"的数据底座，
> 并在同一套口径上完成**单机与分布式引擎的对照实验**，得出选型依据。

**做的是数据工程/数仓，不是机器学习建模。**

## 📊 数据实况（本地实测，可复现）

| 项 | 值 |
|---|---|
| 文件 | `data/raw/accepted_2007_to_2018Q4.csv.gz`（374.4 MB） |
| 总行数（含页脚） | 2,260,701 |
| **有效数据行数** | **2,260,700** |
| 字段数 | 151 |
| 时间跨度 | 2007-06 ~ 2018-12 |
| 主键 `id` | 完全唯一，无重复 |
| 终态不良率 | **≈ 19.98%**（269,360 / 1,348,099） |

**🚨 三个已探明的数据陷阱**（详见阶段二指导书 §1.1、§1.4）：

1. **末行是页脚文本**（`Total amount funded in policy code 2: ...`），非数据 → 读取需 `skipfooter=1`
2. **`member_id` 整列为空**（226 万行非空值 = 0）→ 无法建客户维，改用 `dim_applicant` 申请人画像维
3. **32 行 `issue_d` 与 `loan_status` 同时为空** → DWD 行数 = 2,260,668（差异已登记）

## ⭐ 三个"会做"与"做过"的分界点

| # | 亮点 | 为什么值钱 |
|---|---|---|
| 1 | **申请时点 / 表现期物理分表 + 字段黑名单自动校验** | 信贷数据泄漏是经典陷阱；用结构约束而非自觉 |
| 2 | **E4 数据倾斜完整实验**（量化 → 复现 → 加盐 5/10/20 → 最优桶数 → 正确性验证 → AQE 边界） | Hive/Spark 面试第一高频追问，90% 候选人只有概念没有数字 |
| 3 | **E5 三引擎基准 + 选型阈值**（含"我这个量级其实不需要分布式"的诚实结论） | 区分"会用工具"与"能定方案" |
